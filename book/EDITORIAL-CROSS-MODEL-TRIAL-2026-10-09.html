一、为什么暂不采用既有候选

现有候选确实补出了生涯前史、同时期开发记录、真实人物引语和更多可追溯来源，但篇幅增加 ≠ 传记成立。常见症状：

  1. 逐份采访依次介绍和解释，正文像材料摘要顺接成的读书报告；
  2. 刚出现人物行动就归纳意义、纠正误解或给限制条件，读者没有机会自己理解；
  3. 各节高度类似的“历史动作 → 方法总结 → 边界”节拍，标题在预告意义而不是制造阅读兴趣；
  4. 多种创作者都被同一个克制、平稳、审计性的叙述声线覆盖；
  5. 为了完整覆盖 Case，在同一篇传记中插入过多教育／商业／技术理论；
  6. 把研究不确定性防护写成大量正文免责声明，影响叙事流动。

本轮不要再安装或增加 Humanizer、禁词表、模式评分、模板校对 Gate。 根本实验是：换不同模型和叙事选择，看看真人读者是否能记住人物及其抉择。写作不是新的事实发现任务。

二、实验分工：模型之间不要相互带稿

  • 史料提供者（Codex / Lane B）： 冻结来源包，分别列“可写事实／只能带归属的自述／UNKNOWN 或争议／可用原话和出处”。这份材料必须不含其他模型的段落、文学提纲或评价。若使用 #288 的新增证据，以 693b3de29b75f0c30e61c3cdbbdaebe16b72b583 为可复现的起始快照；最新修订另记，不能混用。严格遵守 AGENTS.md、WORKFLOW.md、docs/project-routing-gate.md、docs/public-research-boundary.md。
  • 独立作者模型 A（如 Reasonix + DeepSeek）： 只读统一事实包和原始来源，写一个真正有连续叙事的中文片段；不得阅读 #283–#289 其他模型已写的候选段落，或本库成篇人物稿，以免不自觉沿用已有结构。只需了解作品、时代与材料事实，不要求将全部研究条目用光。
  • 独立作者模型 B（另一个模型，可为 Codex、其他 DeepSeek 以外模型等）： 用同一事实包、同一字数约束、同一任务独立写，不看 A 的稿子；不同供应商是有价值的多样性，不保证质量更高。
  • 事实审稿人（可以是 Codex）： 在写完后逐条对照 Case / Evidence / 原始来源；有新史实、隐含因果、人物心理或疑似错误引语，集中形成后台审稿说明，不将这些提示插回到每个叙事段落。
  • 真正的主编和读者： 人类作者决定哪个版本有独立的个性、幽默、节奏及继续阅读冲动。AI 自评不能代替真人阅读。必要时另找少量读者试读，未实际发生就标 NOT TESTED。

本轮作者模型只提交候选文件，不修改 profiles/ 正式正文，不提交主分支，不修改 cases/、evidence/、claims/。 GitHub PR 由项目维护者审核合并。

三、分批次试验，不制造三十份待选稿

第 1 关：Kenshi，先验证这个流程有效

题材：2017 年采访中，Chris Hunt 讲述《Kenshi》一个佣兵寻路错进民宅，引发屋主、守卫、同伴介入，最后演化为城市冲突的实际游戏趣事。用它把读者引向一个创造复杂自治系统的人，再用已核的少量生涯事实过渡到程序员转夜间保安、业余／长期制作、早期网站 alpha 销售与团队形成。

来源： - cases/CASE-012-kenshi.md 与 evidence/CASE-012-kenshi-source-ledger.md，特别是 #288 补证 E001、E002、E003、E007/E008（需逐条复核源档；不能凭本任务书替代核验）。 - 2017 GameSkinny 访谈；2015 Siliconera 访谈；Lo-Fi Games 机构资料。 - 保护性边界： 佣兵事件是本人讲述的游戏 Bug／涌现行为轶事，不是现实发生的城市冲突；不能补写旁观玩家动作、具体对白、现场情绪；没有公开的具体家庭预算与逐年准确人员规模不要猜。网站 alpha 销售早于 Steam 对人力的扩大支持；不能倒写收入顺序。

首轮每个独立模型只写800–1300 个左右中文汉字连续文章片段；不是完整 Kenshi 传记。标题可有可无，正文最多两个小节，必要时完全无小标题。文章尾部单独列 3–6 个实际引用，不能混入读者正文。可以按事实改变入口，不强制一定用佣兵故事开篇，但必须解释读者为何会想读下去。

停止条件： 如果换模型后仍写成调查笔记、说教文、事实列表或公式化散文，不要给出新一轮禁词规范。先检查是否任务包把所有理论都当成必写，从源头减负。

第 2 关：Gunpoint，叙事时间和作者个性

第 1 关出现至少一个值得继续的候选以后，再让两个模型写 Tom Francis 的连续片段。至少覆盖：2010 年的开发日志中，他在新战略游戏想法与 Gunpoint 的制作路线图之间选择，检视已经写过但尚未实现的演出、保留游戏交互；与作为 PC Gamer 评论员的职业前史以及 GameMaker 动手制作建立真实的历史关联。

来源： - cases/CASE-007-gunpoint.md、evidence/CASE-007-gunpoint-source-ledger.md（特别是 E008 与 #288 的新增事实）。 - 本人 2010-10-25 开发日志；2010-05-03 开工日志；2013 开发复盘。

重点检验是否能表现 Francis 的真实自嘲、犹疑、兴趣与决策，而不是重复宣布“品味决定命运”。允许有作者观点，但只在它能改变对具体人物的理解时出现。区分 2010 当时判断、2013 回顾、2014 方法论后见总结，不能把它们揉成一个早已知道结果的主创神话。

第 3 关：DOOM，群像和冲突

在第二关后，再让两个模型写 early id 的一个自足片段，优先考虑 Softdisk 的工资与生产训练、夜间制作 Keen、在新公司继续处理旧雇主交付义务，或 Romero 与家长对于计算机／游戏的矛盾（择一为主，不能把两个题材强行揉在一起）。

来源： - cases/CASE-016-early-id-software.md 与 evidence/CASE-016-early-id-software-source-ledger.md； - 对应的 Tom Hall、Scott Miller、Romero 或 Carmack 一手来源；Kushner Masters of Doom 必须指明是较晚出版的二手叙事，不能抄用未经证实的戏剧对白或场景。

这关检验能否真正让不同人物的意愿、约束与合作／冲突相遇；不要求一个千字段落解释完整 FPS 技术史、美国个人主义、游戏 mod 革命和 Ion Storm 后史。

四、交给独立撰稿模型的提示词（可直接复制）

你现在不是研究档案总结员，也不是成功学讲师。请根据我给你的固定历史事实包和可访问原始来源，创作一段可独立阅读的中文历史人物非虚构叙事。目标是让对这位人物和游戏不熟悉的读者，通过具体的矛盾、动作和后果，想要继续读下去。

限制：不得虚构引语、心理、场景布置、时间先后、家庭冲突或人物动作；不确定的重要事实宁可不用。不要模仿另一篇 AI 候选，不照搬研究档案的论证顺序。不要为覆盖材料而覆盖材料：你可自主选取最有叙事价值的事实，也可删除对这一场故事没有作用的史料。

只写这一段历史，不向我讲道理。 读者应有机会自己理解事情的意义。不要在每个事件后插入“这证明……”“我们不能推断……”或今天该怎么办等教学内容。必要的争议交给单独的文末核验说明，不把存在争议的断言写成事实。

首轮以 Kenshi 为对象，约 800–1300 中文汉字，最多两处小标题。正文结束后分隔列出：①主要来源 ②你有意舍弃了哪些材料及原因 ③哪两处最需要事实核验。后两项不属于正式正文。

不要修改任何 canonical 文件，不要向 main 提交。初稿完成即停止，由作者比较阅读体验后决定是否续写。

补充要求： 如果你能访问 GitHub，请从同一已冻结的 Case/Evidence 版本自行选择事实；若只能得到文件包，就严格限于文件包内有出处的事实。不要读取其他模型的候选稿来构思。

五、匿名比较：谁负责什么，怎么裁决

把作者模型的输出保存为 A.md、B.md（随机代号；对应模型身份在单独的审稿记录里保留）。不要把“DeepSeek 写的”“GPT 写的”放在标题或正文。

先不展示来源清单和模型身份，让作者只读两篇正文，写下： - 哪篇更愿意继续读，具体在哪句话／哪一段开始感兴趣？ - 能否记住主人公与至少一件独特的真实行动？ - 哪个片段像文献综述、命题解释、旁白训话或翻译体？ - 哪篇对作品／时代不熟悉的读者也有画面和故事的逻辑？ - 哪篇有真正独立的作者声音，而不是过度添加“文学感”修辞？

不把“看起来更文学”当成自动胜出。先做盲读，再解盲。此后由独立事实审稿逐句检查归责、年份、数字口径、直接引语、因果、回忆时点、UNKNOWN 与历史条件。史实回退是硬否决；未通过事实核验的稿子不进入出版正文。

裁决用三个明确结果：KEEP_EXISTING / REVISE / SELECT_AS_PILOT。选择某个片段仅说明值得扩写，不说明整篇已经批准。

如有第三个模型，可增一版而不改变事实包。实验记录必须披露实际提供商/可确认的模型版本、日期、提示词版本、来源包 SHA、字数范围、有无读其他稿件、是否真人盲评；无法确认底层模型则标 UNKNOWN，不虚构“DS Pro 优于 Flash”之类结果。

六、写入与交付边界

首轮仅允许创建一个独立的模型试写分支及少量新候选文件／审阅笔记；不得覆盖 book/profiles/、book/chapters/、book/life-routes/，不得为讲故事修改研究事实。工作成果尽量放在 book/research-notes/ 中有清晰标识的候选稿与结果报告；实验稿非出版正文，不必进普通读者索引。

来自未合并 PR 的新证据须记录其确切 commit/ref；PR #289 相对 #288 的特殊 base 关系不得误读成已进入 main。需要新增史实则转为单独 Lane B PR。完成后把候选与事实审计分开提交，执行仓库现有 lint、公开研究安全检查及 PR 门禁。

建议下一步： ①保留 #288 作为独立研究审阅，暂缓采纳 #289 的长篇正文；②将此任务书交给 Reasonix/DeepSeek，优先跑 Kenshi 单片段；③再用一个不同模型按同样材料写第二版；④作者盲读比较；⑤仅对被选中的写法扩展到 Gunpoint 和 DOOM。不要再通过无限增补“去 AI 味规范”延迟实际对照。

验收目标： 不是获得三个“据实客观、语句自然、规范齐全”的资料稿，而是得到一段读者愿意继续读、有真实人物独特性、也经得起史实核验的原创中文非虚构叙事。
