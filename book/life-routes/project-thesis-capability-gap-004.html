LR-004 — 我知道想做什么，但团队做不出来：先改作品，还是补能力？

  • Status: READER ROUTE / EVIDENCE-BOUNDED
  • Last reviewed: 2026-10-07
  • Best-fit reader: 有明确作者意图或初步 prototype，团队在美术、程序、动画、系统、叙事、关卡、生产或市场接入方面存在缺口；正在考虑自己学、删需求、外包、找合伙人、招聘或融资
  • Positive comparators: Gunpoint / CASE-007、The First Tree / CASE-042、Nomada / CASE-050、The Witness / CASE-047、Outer Wilds / CASE-049、Croteam / CASE-060
  • Pressure comparators: Playdead / CASE-056、The Magic Circle / CASE-048、Limit Theory / CASE-054、thatgamecompany / CASE-057
  • Mechanism: C015 能力反向立项；能力—项目适配审计
  • Boundary: 这是一套帮助减少错误承诺的选择程序，不是成功率模型、固定人数配方或融资法律意见；具体合同条款必须独立审阅。

先把“做不出来”拆成具体工作

核心机制已经能运行，接下来的工作却可能很不一样：让陌生玩家看懂画面，做出可靠的动画，增加关卡和敌人，建立能重复使用的制作流程，或者准备一份足以说明体验的演示。把这些都叫作“缺人”，很容易买错能力。

缩小作品、自己学习、购买服务、邀请共同作者、招聘和融资，各自改变的责任也不同。一次短期交付可以结束，固定工资要持续支付，共同创始人还需要共享决定权。先辨认哪个问题阻止了体验成立，再判断值得为它承担多长时间、多少现金和哪些难以撤回的承诺。

下面从诊断进入六种选择，最后用决策卡把下一步写成可核的动作。工具用于比较，不要求所有项目走同一条路。

第一关：你缺的是能力，还是证据？

在讨论招聘与融资前，先分清四种不同问题。

看起来像“做不出来” 真正问题 正确的第一种动作 暂时不该做
作品的快乐尚未发生 Product-thesis gap：你还不确定它值得做 缩成能被陌生玩家反驳的 playable 依据愿景扩固定团队
玩家价值存在，但当前人的工种不覆盖 Capability gap：缺真正的新专业判断 借助工具、试做、专家/协作者验证缺口 把所有弱项都变成 full-time 岗位
会做，只是产能不足或迭代速度慢 Throughput gap：缺稳定生产量 切片、批处理、短期合同，必要时招聘 把吞吐量问题误诊为合伙人问题
核心产品成立，却无法被玩家理解或覆盖足够市场 Legibility / market gap 测试定位、体验入口、市场接触 假设增加内容或美术精度就能弥补需求

四个问题可以同时存在。最危险的做法，是把它们都叫“缺钱”，然后试图一次融资消灭所有未知数。

先对“已经确定的作品”做一次证据分级

S0 — 作者意图清楚：能讲清题材、情绪、玩法幻想。尚不足以证明玩家愿意玩。

S1 — 关键机制可玩：存在最小玩法闭环，但主要仍在团队内部测试。可以开始确认技术与设计可行性。

S2 — 陌生人能反复感到目标价值：不是朋友夸奖，而是独立玩家能理解、完成、复玩或主动追问；仍未自动证明市场规模。

S3 — 可辨认的市场证据：有与拟售产品相匹配的受众响应、demo 留存/复玩、有效 wishlist/愿付价或实际购买等；证据质量取决于来源和口径，不能混为“市场成功”。

S4 — 交付约束已测明：知道为了达到可发售标准，具体要补哪些工作、工期与单位成本；它可能早于或晚于强市场信号。

这些是本路线的决策门，不是行业公认的成功率阶梯。不要求所有作品按 S0→S4 单线升级。

只有意图或内部原型时，投入应先帮助你判断体验是否成立。有了陌生玩家的反馈，并找出反复发生的制作瓶颈，才更有依据讨论长期岗位和扩张。早期也可以融资，但钱到账不会自动使玩家价值得到验证。这是本路线的承诺审计建议，不是对历史项目共同顺序的描述。

第二关：先判定哪项能力必须留在作者核心

对于每个缺口，逐个回答四个问题：

  1. 它决定作品“是什么”吗？ 如果改变这项判断，玩家体验和作者性会发生根本变化吗？
  2. 它需要每天和核心玩法一起迭代吗？ 还是可以编写规格、验收并交付？
  3. 需求是一次性的，还是连续几年都存在？ 是否足够稳定到支撑固定薪酬？
  4. 为什么现在必须解决？ 它是在验证玩家价值，还是仅在让作品“更像正规游戏”？

由此得到一个初步分流：

  • 作者性关键、需要高频共创 → 优先考虑由现有主创学习到足够深，或邀请拥有真实创作权的核心协作者；未必需要共同创始人。
  • 可以定义边界、可独立验收 → 优先考虑购买素材、授权工具、短期 specialist 合作或外包。
  • 可预期、高频、长期且可核算产能 → 可能值得 permanent hire。
  • 即使补齐也不能提升玩家价值或市场可读性 → 应先删除、替换或推迟。

合同工、员工、共同创始人不是三档价格，而是三种不同的权利、组织摩擦和可退出性。

第三关：六种真正不同的动作

A. SHAPE — 围绕核心体验重新选择要做的东西

什么时候优先考虑： 产品仍在验证、现金紧张、缺口主要来自可以被重写的表现或内容义务。

你先做的测试： 写出“玩家必须感到什么”，再做两个版本：一个继承传统品类规格，一个用现有强项重新表达同等核心价值。把二者交给陌生人比较，而不是比较内部制作完成度。

历史对照： 2010年，Tom Francis重新审查《Gunpoint》的路线图时，发现自己因为已经想好、写好了剧情，便自动纳入脚本化段落、重要人物和预定发展。这些非交互段落需要大量代码，给游戏本身增加的东西却很少；已有写作投入没有成为保留它们的理由。CASE-007账本E008 记录了这次具体取舍。2014年，他在发售后的方法文章中，又把《Deus Ex》里巧妙潜入建筑的兴奋感，与《Gunpoint》可重复使用的电气连接规则联系起来；这是后来的归纳，不能倒写成所有早期决定都遵循同一套明确方法。

David Wehle面对的约束不同。2016年，他已有技术美术工作和育儿责任，在开发中的文章里主动选择短而简单的项目，使用购买或授权的素材、脚本，把环境设计、叙事和用户体验作为强项。CASE-042账本E005 支撑这些选择，但不能补出家庭预算或照护分工。两条路径都让作品的制作义务发生变化；这里比较的是具体取舍，不是用两次成功证明低成本必然有利。

禁止推论： 改小一定卖得更好；画面不重要；低成本一定激发创造性。

停手信号： 进一步压缩已摧毁玩家最初想体验的东西，或让市场再也无法理解品类承诺。此时需要能力，而不是继续删。

B. LEARN — 只学习必须留在你手里的那部分新能力

什么时候优先考虑： 缺口位于作者核心；决策必须每天参与玩法循环；外包会造成漫长沟通和反复重做；学习成本仍处于可控的短试验窗口。

你先做的测试： 给自己一个限定任务，例如完成一个可评价的角色动画状态机、战斗手感样例或可复用工具链。比较实际达到的质量、迭代速度和维护负担，而不是衡量“我上了多少课”。

历史对照： Croteam 制作《The Talos Principle》时继续使用Serious Engine/Editor，新增的解谜体验则需要交叉试玩、难度统计、外部alpha和自动QA。2015年的开发者复盘记录了这些方法及反馈后的删改；既有工具仍有用途，新判断也有具体的学习对象。

压力例： Limit Theory 提醒：技术能力持续进步，并不代表完整产品的剩余义务在减少。

停手信号： 学到的东西能做越来越多演示，却不能更快验证、完成或维护目标产品。

C. PERIPHERALIZE — 买结果与专长，不买永久组织

什么时候优先考虑： 核心团队已有清晰规格、可以验收质量；需求是有限批次、专业领域或明显的产能尖峰。

你先做的测试： 先签一项最小可验收交付——一组角色、一段 music、一次 porting compatibility audit、一套视觉探索，而非“包整款游戏”。同时确认二次修改、源码/工程文件、授权、署名和资产可持续维护边界。

历史对照： David Wehle在《The First Tree》开发期使用授权素材和脚本，PC发售后又由DO Games承担主机移植与性能优化。Subset Games的《Into the Breach》保留很小的作者核心，音乐、音频、美术和写作等工作仍有外围协作者参与。两案都需要把核心人数与完整生产人力分开；具体合同成本和各人的加入时点，继续以 Wehle档案 与 Subset档案 的已知边界为准。

压力例： 外包不能自动替代缺位的创意总监：如果你连审美标准和验收权都无法独立建立，购买一个资产包可能只是生成下一轮返工。此为路线判断，不是某个 Case 的直接结论。

停手信号： 每次交付都需要核心团队重新定义产品；沟通/返工成本持续大于能力补位收益。

D. COMPOSE — 用共同作者补核心，不要把股权当免费工资

什么时候优先考虑： 缺口不可外围化；对方必须共同定义产品，而不只是执行你的 specification；双方需要共同承担多年不确定性，并愿意共享决定权。

你先做的测试： 在决定长期绑定前完成一次短期、真实的小型共同创作；让双方各自拥有实质决定权，并故意提前讨论一次冲突场景：目标、范围、现金、下一作、署名和退出。

历史对照： Nomada / GRIS 的Conrad Roset带来职业插画能力和作品设想，Roger Mendoza与Adrián Cuevas带来AAA程序经验，三人共同建立围绕作品的公司。这里需要共同作者关系，具体股份与协议仍未知。

压力例： Playdead 的Arnt Jensen主导作品方向，Dino Patti承担公司建设等职责；团队完成《LIMBO》《INSIDE》后，Patti仍在2016年退出，后来的报道和本人说法揭示创始人冲突。作品完成没有使合伙永久稳定；哪些权限安排可以避免分歧，现有材料不能替双方回答。

停手信号： 无法明确 product authority、equity/vesting、deadlock、IP/credit 和离开后的持续义务；这时你还没有一个可长期运行的 cofounder 结构。

E. HIRE — 买可重复产能，但要先证明岗位存在

什么时候优先考虑： 你已经有 S2/S3 级的外部价值证据，且至少能明确一项持续瓶颈；反复购买合同工的边际成本、返工与知识流失高于内部化。

你先做的测试： 先用一次受限合同或短生产周期记录真实产能、协作质量和验收率，再确定岗位职责与可持续现金义务；固定成本必须覆盖到下一个可验证的里程碑及失败退出，而不仅是支付一个月工资。

历史对照： Jonathan Blow用《Braid》收入为 《The Witness》 补入美术、建筑和景观等专长，首作零收入团队不能省略这项资金条件。Kenny Sun 则经过个人作品、职业工作和发行合作，到2025年的《BALL x PIT》才明确说自己首次真正带领团队。两条历史记录了不同的能力扩展，不能据此把协作者一律当作长期员工，或声称两人执行过同一套招聘验证程序。

停手信号： 招聘理由只能写成“正规游戏应该有这个岗位”，写不出已验证体验对应的持续工作队列。

F. FINANCE — 融资不是第七种能力，它只决定谁来支付能力以及谁能约束你

什么时候考虑： 已经确定应该购买什么能力、为何当前非买不可，以及这笔钱是否会把组织变成必须继续融资才能维持的机器。

四种资金不可互换：

资本路径 对应案例 能买到什么 主要风险与边界
Founder money / 前作留存 The Witness、Into the Breach 新 specialist，或更长的低承诺探索时间 私人机会成本、现金损失；前作成功不可复制
Grant / non-dilutive House House 有针对性的开发期、完成资金与专业能力 申请资格、地域、资金用途与拨款节奏；非所有团队可申请
Publisher / platform Outer Wilds、Croteam 制作、发行、平台支持、市场接入等不同能力束 milestone、IP、平台、recoup 和批准权须逐合同核；案例不证明特定 veto 已存在
Company equity / VC thatgamecompany 把发行、营销、客服等能力直接建成公司组织 稀释、董事会、投资回报、下一轮资金依赖；board seat ≠ 自动创意否决权

融资前先说清一个问题： 如果明天资金到账，哪项已经确定的玩家体验或交付任务会因此更快实现？如果答案只是“团队终于可以像一家正式工作室运转”，就还没有说明资金如何服务作品；融资本身也不构成玩家价值的验证。其他合同和治理问题仍须分别检查。

第四关：先做哪一个动作？——决策表

当前可核处境 先尝试 可能升级到 必须警惕
S0 / 只有概念，作者能力偏科 SHAPE + 限定 LEARN：做一个足够便宜的反驳性原型 玩法真实成立后，再寻找 core specialist 用画质或人数替代产品真相
S1 / 可玩但陌生人不买账 先辨别是 onboarding / 核心乐趣还是视觉 legibility 如视觉阻止理解，先小额购买 visual direction 从“看着廉价”直接推出“缺整个美术部门”
S2 / 玩家价值已经成立，缺可独立验收的资产 PERIPHERALIZE：限定输出和返工界面 稳定重复需求才 HIRE 短期资产尖峰变成永久 payroll
S2 / 价值已成立，但另一种作者能力必须长期共同定义体验 小型共创实验 COMPOSE，签清治理结构 把互补劳动当成免费股权交换
S2/S3 / 有真实需求且长期产能不足 有限合同测试吞吐与知识成本 HIRE / FINANCE 资金先于具体岗位；扩张先于证据
旧技术让新玩法不能成立 保留仍有效底座，单独验证 player thesis 分阶段换工具 / 专家 为了证明创新而同时更换全部技术
已投入很久，局部产出很好但可玩产品始终不闭合 立即设 stop condition / 删系统 / 重估项目 SHELVE / PIVOT / KILL 技术或设定沉没成本主导决策

注意：PIVOT 与 KILL 也是主动设计选项。不是每个愿景都值得用借贷、股权或多年不领工资来补齐。

两个反例：为什么“团队很适配”仍不够

Brigador 的工程、美术管线和战斗口味与作品契合，2015年也已进入Early Access。2016年正式发售仍出现商业不足；Hugh Monahan指出，展示让人以为它是双摇杆射击，实际玩法却复杂得多。能力补足没有自动使陌生玩家正确理解作品，这项诊断也不能解释全部销售结果。

The Magic Circle 把三位核心创作者的系统、AI和叙事经历变成了作品。2016年Jordan Thomas却把当时销售称为不可持续，并讨论品类、受众和营销预算问题。Question后来继续制作《The Blackout Club》，财务是否恢复仍未知。再加程序能力，不能自动回答这些市场问题。

因此，本路线把制作与市场分成两次检查：

  1. Creator–Project Fit：我们有没有能力以合理代价做成这件事？
  2. Project–Market Selection：即使做成，有没有足够清楚、足够大的付费理由支持未来生产？

第一题答“是”，不会使第二题自动答“是”。

两分钟读者自查：把“我缺人”翻译成可核动作

以下是一张可以直接复制填空的决策卡。

作品的不可替代体验： 玩家真正应该感到/能做的是什么？
目前证据门： S0 / S1 / S2 / S3 / S4；证据来自谁，时间和条件是什么？
当前最短板： 不是岗位名，而是“谁因缺乏哪种判断/产能，阻止哪项具体玩家价值出现？”
能力属性： 作者核心 / 高频协同 / 可验收外围 / 可删除义务？
最便宜的下一次实验： 不招人、不融资，能否先验证缺口真的是它？
候选动作： SHAPE / LEARN / PERIPHERALIZE / COMPOSE / HIRE / FINANCE / SHELVE；为什么不是成本更低的替代？
最大不可逆成本： 股权、IP、固定工资、债务、长期承诺、家庭时间或声誉？
资源覆盖： household runway、公司现金、交付窗口、失败后退出条件；若未知，写 UNKNOWN。
升级门槛： 哪项外部证据出现，才值得投入下一级成本？
止损条件： 到什么日期或什么验证失败时，降规格、换路、暂停或终止？
正反案例： 我最像谁？最可能重演谁的错误？哪一项相似仅是职业标签？

关键不是打一个“项目值得做 86 分”的假精确数字，而是明确到底什么新事实可以改变你的决定。

一个虚构的双人团队：如何使用这张卡

这是一个虚构教学示例：双人PC战斗游戏团队中，A负责战斗设计、系统和世界观，B负责程序。核心玩法能运行，敌人可读性、动画和场景美术却还没成立；他们正在考虑长期招聘美术，或先做大量AI视觉素材。按前面的卡片，可以先把待验证的缺口写清。

如果陌生玩家看不懂敌人意图，先用灰盒、临时精灵和动作提示，必要时配合短期动画/视觉专家，做出一个完整可测试的敌人，观察玩家能否读懂并作出操作选择。如果缺的是统一的视觉身份，则可以安排一次付费方向探索，用少量角色、场景和UI比较可读性与市场反应。增加素材数量并不会自动完成这两种验证。

视觉标准明确后，若持续制作整套资产仍超出团队产能，再评估长期岗位；若美术方向需要长期共同决定作品，则要同时讨论作者权限。长期艺术总监、员工与共同创始人带来的权利和责任不同。这个例子演示怎样拆问题，没有真实测试结果，也不要求所有双人战斗游戏按同一顺序行动。

年份、资本与现实边界

可迁移的机制： - 按玩家价值定义能力缺口； - 让验证先于不可逆承诺； - 区分 authorial core、specialist perimeter、长期 payroll 与 founder equity； - 把 capital source 和 decision rights 同时记账； - 把 market selection 与 production feasibility 分开。

不可直接照抄的历史条件： - 2013 Gunpoint 的 GameMaker / PC Gamer 工资与传播位置； - 2016–2017 The First Tree 的 GIF/Reddit/Imgur organic reach； - 2016–2018 GRIS 的 boutique-publisher、视觉新鲜度与艺术成本； - 2014 Croteam 自研引擎与 Devolver 的发行关系； - 2010s 《Braid》后 Jonathan Blow 的 retained earnings； - 不同国家、家庭、社保、grant eligibility 与融资契约； - 2026 AI 生成、廉价资产、coding agents 的现成能力：它们可能减少执行成本，却不能自动替代作者判断、版权审查、集成、测试、长期维护和付费市场证据。

本路线没有创作者成功率统计，不提供固定“几个月该辞职 / 几人该扩编”公式。若你是从大厂高绩效岗位转换作者身份，可同时阅读 LR-001；若当前有稳定工资，需要安排阶段性投入，参照 LR-002；若房贷、育儿或照护成本高，先核对 LR-003 的家庭现金风险。其他处境请回到 决策总分诊。
