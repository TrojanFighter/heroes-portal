本轮重点不是继续提高覆盖率，而是把 runway 的不同生产含义 拆开。

一、Runway 不是一个变量

现在至少已经能稳定区分六种结构。

1. Salary / Day-job Runway

代表： - Gunpoint - The First Tree - Minecraft early stage

机制：

stable salary
→ low-commitment prototype
→ stranger/market evidence
→ quit threshold
→ full-time switch

优点： - 个人现金风险低； - 保留职业退出路径； - 可以把辞职延迟到 evidence 之后。

缺点： - 时间碎片化； - 疲劳； - household / childcare 可能吞掉剩余时间； - 某些类型不能靠夜晚/周末形成有效连续生产。

因此：

工资的价值不是“安全”，而是购买低承诺试错期。

2. Freelance / Contract-work Runway

代表： - Manor Lords - Darkwood - Rocket League / Psyonix

但三者完全不同。

Manor Lords

自由职业主要用于：

维持个人生活，同时保留 hobby / part-time development。

当 Patreon / MegaGrant 到来后：

先买回作者自己的 full-time focus，再扩 specialist perimeter。

Darkwood

paid contract work 是：

首次商业项目早期的生存桥梁。

它没有形成长期组织资本，反而切碎原创时间。

Rocket League / Psyonix

work-for-hire 是：

十多年维持公司、团队、Unreal 工程能力和 AAA quality exposure 的组织性 bootstrapping。

它同时积累： - cash capital； - capability capital； - team tacit capital； - client network。

所以不能泛泛建议：

“独立工作室可以接外包养自己。”

真正要问：

  1. 接活只是在卖时间，还是在积累可复用能力？
  2. 它是否保住了你真正需要的共同团队？
  3. contract work 是否把最强成员全部抽走？
  4. 它是否建立 market / platform /技术关系？
  5. own-IP 是否有受保护的时间预算？

3. Previous-game Reinvestment

代表： - R.E.P.O. / semiwork - Landfall - Into the Breach

R.E.P.O.

Voidigo 的六年开发： - 提供团队 tacit capital； - 提供有限收入； - 也制造“不要再六年做一次错误方向”的反向经验。

于是第二作强调：

fail quickly。

Landfall

前作收入逐步形成： - studio cash； - brand； - Steam history； - community； - prototype portfolio； - right to fail repeatedly。

Into the Breach

FTL 成功没有被自动兑换成更多 permanent employees。

而是兑换成：

时间、删除权、低承诺 private exploration。

因此 previous-hit capital 至少有三种用途：

A. 买人
B. 买时间
C. 买失败次数

哪一种最值钱，取决于当前 binding constraint。

4. Public-market Self-financing

代表： - Minecraft - Factorio - Kenshi - Among Us（部分）

结构：

playable before complete
→ real users
→ payment
→ feedback + runway
→ continued development

Minecraft

early paid Alpha 直接建立辞职阈值。

Factorio

crowdfunding 之后迅速改成 sustained paid alpha / preorder。

Kenshi

EA 收入从“个人长期低收入”切换到“购买团队能力”。

Among Us

较弱版本： - PC 收费； - telemetry； - small creator spikes； - 长期低可见度； - 直到 2020 才出现 extreme right-tail。

这说明：

public-market self-financing 不等于 market success already known。

它可能只是持续买下一轮时间。

5. Grant / Non-dilutive Runway

代表： - Manor Lords / Epic MegaGrant - House House / Film Victoria

Grant 的关键价值不是“免费钱”。

它可能购买：

  • founder time；
  • specialist capability；
  • polish；
  • accessibility；
  • stronger demo；
  • bargaining power；
  • completion。

House House 尤其清楚：

grant
→ project evidence / local specialist capacity
→ publisher negotiation
→ market/release perimeter
→ hit
→ retained earnings

所以：

non-dilutive capital 最有价值时，往往不是让 scope 变大，而是让 evidence 变硬。

6. Community / Mod / Contest Runway

代表： - Tripwire - Project Wingman

它们不是完全“没钱做”。

而是：

public artifact
→ community feedback
→ credibility
→ collaborators
→ contest / crowdfunding / publisher
→ commercial production

Tripwire：

mod → MSUC → company。

Project Wingman：

public alpha → local/community signal → Kickstarter → commercial completion。

这是一种 credibility runway。

它购买的首先不是工资，而是：

下一层资源愿意相信你的理由。

二、Evidence-Following Scaling：什么时候才应该从 solo / tiny core 扩团队？

这一轮最稳定的正向模式是：

core thesis
→ playable evidence
→ repeated external signal
→ identify specific bottleneck
→ buy that capability

而不是：

idea
→ raise money
→ build team
→ hope team discovers product

House House

grant 先买： - refinement； - accessibility； - local development labor。

publisher 再买： - sound； - platform； - release； - market perimeter。

能力是按已知缺口增加。

Manor Lords

Patreon / MegaGrant 先让作者：

stop routine freelance work。

然后才外包： - mocap cleanup； - illustrations； - QA； - marketing/distribution。

Project Wingman

公开 alpha / community evidence 已存在后：

Kickstarter 放大 runway。

R.E.P.O.

已有 Voidigo 团队 tacit capital； 新项目反而通过连续 pivot 先减少错误承诺，而不是立刻加人。

因此：

evidence-following scaling = 资源升级必须跟着已经观察到的 bottleneck。

三、提前扩张的典型危险

现有失败矩阵已经出现三种：

1. Unknown-product scaling

核心 loop 还没证明，就先建大组织。

代表压力： - SYNCED

2. Organization-shaped design

因为已经有团队/投资，所以项目必须变成足以“养这个组织”的东西。

代表压力： - 多个 commercial / live-service cases

3. Capitalized Error Persistence

钱越多，错误方向越晚接受现实裁决。

所以资金真正的风险不是：

“投资人会不会干预创意”。

更一般的是：

资金是否让错误比证据活得更久。

四、Work-for-hire 到底什么时候值得做？

现在能给出更精确的判断框架。

值得做，当它同时生产至少两种资本

例如 Psyonix：

  • cash；
  • Unreal skill；
  • AAA production literacy；
  • long-lived team；
  • industry relationships。

所以 contract work 不是单纯换现金。

价值有限，当它只制造 runway

例如 Darkwood early contract work：

  • 能活；
  • 但切碎原创；
  • 并没有直接解决 long-project estimation 弱点。

这不等于它“没用”。

它只是：

survival bridge rather than capability engine。

Creator Debugger

接一个外包项目前问：

  1. 它能活多久？
  2. 它会带走多少最稀缺的连续创作时间？
  3. 它留下什么 reusable code / process / network / team capital？
  4. 它与 own-IP 的能力需求是否相邻？
  5. 做完后，项目更容易还是更难重新启动？

如果答案只有：

“能付三个月账单”

那它是 runway。

如果答案还有：

“能留下技术、团队和客户关系”

那才是 capability-building service work。

五、Previous-hit revenue 到底该买什么？

成功后最危险的行业默认动作之一：

招更多人，做更大项目。

但现有案例给出至少四种更理性的用途。

A. Buy time

  • Into the Breach

B. Buy repeated failure

  • Landfall

C. Buy missing specialist capability

  • R.E.P.O. / later projects
  • House House next stage

D. Buy organizational survival

  • Psyonix historically

所以“前作赚到钱”之后真正的问题不是：

下一作预算应该多大？

而是：

上一作成功后，哪个 constraint 已经变成新的最短板？

六、Failure Residue：失败/弱势前作到底留下什么？

这轮最重要的新比较之一。

SARPBC → Rocket League

商业影响弱，但留下： - exact core mechanic； - player behavior； - accessibility problem； - team expertise。

residue 很高。

Voidigo → R.E.P.O.

没有制造财务安全，但留下： - team； - art/animation/music tacit capital； - community； - revenue； - 对六年周期的反感。

residue 很高。

Darkwood crowdfunding miscalculation

资金模型失败，但留下： - backer community； - public credibility； - playable product； - 下一层 EA 入口。

failure 本身被接入下一融资层。

Among Us 2018–2020 modest phase

两年不爆，并不等于零资产。

留下： - netcode； - telemetry； - PC version； - community； - operational knowledge。

2020 right-tail 来时，这些决定团队是否有东西可被放大。

因此：

项目失败不应只记录净亏损。

还要记录：

  • code；
  • tools；
  • playable system；
  • audience；
  • team tacit capital；
  • platform credibility；
  • market model correction；
  • next-project option value。

七、第一版 Runway Choice Matrix

你的条件 可能的 runway 最大优点 最大危险 代表案例
有稳定职业 salary/day job 低个人现金风险 时间碎片化 Gunpoint / Minecraft
能接专业自由职业 freelance 可调度现金流 own-IP 被切碎 Manor Lords
是小工作室，有客户 work-for-hire 保住团队 + 能力训练 client work 吞噬原创 Psyonix
有前作收入 retained earnings 控制权高 自动扩大 burn Into the Breach / Landfall
已有 playable paid alpha / EA feedback 与 runway 同源 过早承诺 / EA debt Factorio / Kenshi
有公共资助资格 grant non-dilutive 依赖项目/地区窗口 House House / Manor Lords
有社区 / mod / alpha credibility ladder 低资本验证 社区不等于付费市场 Tripwire / Project Wingman
有 publisher interest advance/periphery 买专业外围 governance / recoup / milestone House House / Outer Wilds

这个矩阵只帮助选择：

哪种风险结构更接近你。

不预测成功率。

八、当前覆盖率已经足够开始做“人生场景组合”

Life Audit 不再只是资料回填。

现在已经可以组合：

24 岁单身程序员，有全职工作

优先： - Gunpoint - Minecraft early - Kenny Sun early

合理实验：

salary-funded prototype + public evidence + quit threshold。

31 岁大厂制作人，有积蓄但怕旧函数

优先： - Papers, Please - The Magic Circle - Sultan’s Game - Sea/月下研究

合理实验：

极小 evidence prototype + explicit objective-function reset。

35 岁有房贷孩子

优先： - The First Tree - 022 中国 household cases - Manor Lords（只比较连续时间购买，不比较家庭）

合理实验：

先解决 household burn 与连续时间，再谈 scope。

已有一款赚钱作品

优先： - Into the Breach - Landfall - House House

合理实验：

先问“买时间 / 买失败 / 买能力 / 买团队”哪个最值。

高技术 founder

优先： - Factorio + Limit Theory

合理实验：

technical stop condition 必须写在项目 governance 里。

九、下一步

P1 完成后，不需要继续机械追求 56/56。

下一步更高价值的是：

  1. 从已经 SUBSTANTIAL 的 22 个 Case 中，生成真正 reader-facing 的 Life Risk Routes；
  2. 给每条 route 写： - 适用处境； - 最小实验； - quit / scale threshold； - forbidden inference； - 代表成功 / 失败案例；
  3. 把尚未审计的 20 个 Case 只在它们能填补某个 route 缺口时继续回填；
  4. 后续所有新 Case 默认按 Life Audit schema intake。

也就是说：

案例库已经不需要为了数量继续长；接下来应该开始把 evidence 压成人生决策界面。
