  • Status: RESEARCH NOTE / CONTEMPORANEOUS FAILED ATTEMPT + SHIPPED-UNDERPERFORMER + TEAM DISSOLUTION + INSTITUTIONAL SURVEY / PRE-CLAIM

Gate 真实观察单位 失败可能意味着 明确不能推断
AUTHOR ACCEPTANCE / VALIDATE IMPERFECT 人/作品与本人公开反馈 写好了框架，无法接受不完美的可试玩原型，迟迟不公开 当事人不够努力、不自信由中国教育/所在公司造成

另有第五个上游门：从未参加过任何活动/没有公开原型的潜在作者（家庭许可、设备、空闲和经济负担）。本轮四种资料均已选择“敢于留下公开记录的人”，无法直接测量真正不可见的FRAME D NEVER_ENTERED；参见038的Frame D设计。

1. 中国反例一：呼兰Alex /《RESTART》2022，已任项目主程却未完成私人游戏

Original author trace: 2022-01-06 B站开发者本人《记录一次失败的独立游戏制作》： https://www.bilibili.com/video/BV1om4y1S7qU/

公开信息来自作者上传视频的描述正文，而不是我们观看/逐帧分析完整视频；署名/岗位/职业时间由本人自述，未由雇主核实。

可确证的事实

  • 作者称幼时游戏经验丰富，为进入游戏行业改变了大学原专业方向；正式接触编程/Unity大约一年半，当时已在一个较老项目担任主程，能从本职项目安排出一些私人时间。“主程”是本人岗位表述，不代表从事该职位多年、更不等于被工作室授权做私人项目。
  • 独立想制作有明确人生主题的2D作品RESTART，但截至2022视频时没有成功做完并公开上市；并非缺少“题目想象”的纯执行人员。
  • 他本人列明自主搭过缓存池、资源加载、配置表、存档、FSM、AB资源框架等，并发现自己事前设计的大框架并非2D小项目都用得上。可观察对技术基础设施的劳动，不等于完成了一次向陌生玩家展示的游戏闭环。
  • 作者明确将中断的重要原因归为越做越感到作品不能达到自己期望、担心被玩家拒绝或自己羞于拿出来。这是第一人称自我解释，不代表心理疾病诊断，也不能把其归因为学校或中国人的“本质”。
  • 作者感谢合作的美术同学与GF社群成员，所以不是毫无他人支持的绝对solo；目前没有证据证明COLLABORATOR_EXIT造成中断。
  • 作者明确称希望以后再制作、未来继续；因此只允许编码PROJECT_UNFINISHED_AS_OF_2022 + AUTHOR_RETURNS_INTENDED，不能编码CREATOR_RETIRED_AFTER_2022。2023–26是否有其它作品/同名账号仍UNKNOWN。

与商业游戏技能和应试教育的竞争性解释

可提出的H: 一个已有相当局部技术执行能力的从业者，如果对自己作品不够满意、不能容许公共试玩，则TECHNICAL_CAPITAL→PUBLIC_ARTIFACT的门槛未跨越；把写完工程模块当为作品建好了“主干”可能产生INFRASTRUCTURE-FINISH ILLUSION。

必须保留其它解释: 作者当时Unity年资并不久、对场景和美术有不同专业欠账；技术体系是其主动学习方案；商业岗位、家庭和学校没有被证据证明直接造成对外发布焦虑。没发表不等于没有积累可迁移编程技能或应受到羞辱。

Direct comparison: 亚恒2018在10章仅做出6章时把写好的剧本削减、公开可玩的Jam原型；呼兰Alex的2022文字则说明没有同样越过公开不完美的门。两人职业/时代/支援不同，不能把个体结果当国别教育差别。

2. 中国反例二：LZY / szhshp /《昆仑工程 Project Kunlun》，2024正式上市但市场纠错过晚

2024-08-12 开发者本人公开详尽复盘： https://szhshp.org/post/indiegamedevreview 同作者官网作品页： https://szhshp.org/games P0 Steam商店作品与署名： https://store.steampowered.com/app/2546720/Project_Kunlun/

创作者不是首试首次开发

  • 作者自述少年做过RPG Maker小说改编但烂尾；大学期间用C做俄罗斯方块，用Java制作Android小游戏，广告收入总计不足10元；工作后再次尝试GameMaker又中止，长期没有新的游戏项目。
  • 本职行业不在游戏行业，自主游戏在业余完成；持有较大量主机与单机游戏阅历，官网明确称截至2021年收集并评价了约470款游戏。“玩得少”不能自动解释其失败。
  • 2022年底—2024中开始学Rust并设计原型，2023年2月浏览器小程序、2023年3月POC、6月买Steam槽位、2024年5月整体测试，Steam商店按时区呈现2024-06-27发售，作者博客记2024-06-28发售；应分别注明时区/展示日，不指为事实冲突。

完成≠回本，持续迭代≠可靠验证

  • 大量模块和关卡开发后才发现敌方子弹逻辑、音乐同步、难度分层的结构问题，作者说明Stage 4以后曾反复从第一关重构，增加了已经完成段落的返工。
  • 他自述关卡亲自反复调试上千次，导致熟悉敌人位置和行为；作者认为退款意见主要涉及too hard，即使自己已降低难度。这是作者自己对退款留言的总结，未读到Steam后台退款数量与理由分布，不得当客观高难度投诉比例。
  • 作品由最初STG逐步变为带节奏游戏/故事的混合型，他自述当时没有充分理解目标受众/营销，并认为发售前应做Demo以验证而非一年全部做完。
  • 自报约人民币2000元部分现金支出（但还列单独电脑购置、Copilot、时间、约400元音轨授权等）。这并非项目所有现金成本或经济成本；绝不可写2000元项目完整投资。
  • 其中AI素材自述上千次图片试生成只有极少符合期待，仍大量手工PS；机器生成初稿没有消灭审美判断、风格一致性、人工校验与返工成本。首次发行日期、Steam现时2条评论不代表销量/退款总量；没有收入后台与净利润。
  • 作者文章中段有“可能暂停独立游戏”，文章结尾又反转说自己已经在设计下一个游戏。正确编码：2024_UNSATISFACTORY_MARKET_OUTCOME + NEXT_PROJECT_DESIGN_INTENT，并非2024决定永久退出。官网截至观察时仅一款Steam明确列出、2026后续产品未知。
  • 当事人同时反思“一名资深玩家也不自动懂游戏设计”；这与Gunpoint Francis通过十来位陌生测试者主动改跳跃按键的2010史实有明显FEEDBACK TIMING差别。但作者不会玩不够游戏的结论在这个样本显然站不住。

本案的新机制

TECHNICAL COMPLETION ≠ AUDIENCE LEGIBILITY ≠ FINANCIAL SUSTAINABILITY。

某人甚至可以完成G3 playable与G5 ship，但在G4 stranger correction上太晚，导致自己成为测试熟练度严重偏高的“假普通用户”。这是一种非常适合教育和能力反训练的真实相反证据：能力积累不等于能及时否定自己为之努力的判断。

3. 西班牙队伍《The Swarm》2016：团队越改越好，却因scope与人力断裂取消

2016-11-09 Javier Ansoleaga代表Evolve Games原创公开 postmortem： https://www.gamedeveloper.com/business/learning-from-failure-post-mortem-of-an-unborn

  • 开发《The Swarm》前约三个月preproduction，原计划约一年内完成；开发约六个月后取消本作，说明不是见面只写构想就失败。
  • 几个月持续修改机制，使团队认为游戏越来越完整且有价值，但范围不自觉增长；作者复盘称新的内容至少需要约两倍原团队及两倍生产时间，属其当时估算非独立审计。
  • 4位团队成员有2位因个人或经济问题离开，剩余两人感到难以维持原有项目；当事人没有将离开者写成“背叛”或没有创新信仰。其公开说法属于团队成员离开带来的能力缺口＋人月约束，并未公开个人诊断/家庭收入，不要继续推。
  • 两位留下的成员在危机会议后决定取消项目、重组团队、选择新方向；截至2016文稿，他们声称新团队、新项目已经启动，而2017以后是否盈利/成功、两名离开者人生状态未知。
  • 这里不能把CURRENT_PROJECT_CANCELLED写成EVERYONE QUIT GAME DEVELOPMENT。与中国亚恒10章→6章的设计收敛对照，Evolve选择PROJECT_KILL / AUTHOR_REENTRY（至少本人表示计划），也不意味着他们“更会经营”或更有钱。
  • 此案例还构成CAPABILITY_COMPOSED长期可靠性负控制：人才初始互补≠项目在财务、生活和团队生命周期上稳定。

4. 美国/加拿大占较多的开发者行业问卷：署名流失风险既不等于制作能力，也不等于项目已经失败

P0 IGDA + Western University，2024-05-02发布2023 DSS： https://igda.org/news-archive/press-release-the-igda-and-western-university-release-2023-developer-satisfaction-survey/

  • 777自愿回答（2023-05-17至2023-10-20），其中58%工作在美国或加拿大；并非中国/美国可比抽样、不能将IGDA数值推全球/美国全部从业者分布。
  • 48%认为其工作室有游戏署名政策；71%有信心会在在研游戏的正式credit里署名；设想在游戏发售前离职/合同结束时仍有信心署名的比例降到41%。这测的是主观信心在假设环境中下降，不代表全世界59%实际离职员工没有署名。
  • 28%称工作包含crunch；25%称有不归类为crunch的延长工作时间。这些问题可能与个人业余时间形成竞争，但没有独立估计出“多少人的业余游戏因此永远没做完”。
  • 80%受访者取得过某种college/vocational/university文凭（网站原文）；它说明该受访人群不是“没有正规训练”的对照样本。
  • 署名≠IP、作品所有权、能否引用公共作品集、能否聘人/独立发题；而且在前公司工作有保密合约，不能因抽象“作者信用”鼓励泄露项目或去猜受访者的就业合同。

关键新增CREDIT_PORTABILITY机制：

EMPLOYED PRODUCER SKILL ACQUIRED
  ├── CREDIT FOR SHIPPED GAME (officially portable)
  ├── PROJECT CANCELLED BEFORE LAUNCH (no official work credit visible)
  ├── EXIT BEFORE SHIP (credit uncertain)
  └── NDA / IP constraints (cannot freely show original assets/prototype)

这不是已经测量出来的四状态人数，而是下一轮EMPLOYED→AUTHOR研究须区别的权利边界。一个非常会做业务的人，也许几年来没有以合法公开材料向个人作品赋权的机会；但不能从“受雇工作没署名”直接认定本人已经有被抹除的原创构思。

5. 对055的“做题家/技术崇拜/创新神学”命题做更精确的判定

H055-1：有了执行能力仍不具备“交给外部世界裁决”习惯

2022《RESTART》作者能写框架却不愿发表不满意的作品；2024《Project Kunlun》作者完成工程却晚发现市场与难度失配。两者机制不同：前者提前被自己的质量门槛阻断，后者在发售以后才遭遇外部评价。

这足以说明EXECUTION_CAPABILITY、SHIPPING_CAPABILITY、UNCERTAIN_RESEARCH_DECISIONS与PUBLIC_FEEDBACK_TOLERANCE是不同能力。不足以证明“中国高学历做题家普遍如此”，当事人也没有明确说其困难由应试教育造成。应当把该成因留为可由其他样本、学校课程对照、时间序列验证的 H。

H055-2：更多人手也不能替代项目可持续性

《The Swarm》实际经历4→2与scope翻倍，“找一个能力互补共同创始人”不是稳定制作权的充分条件。成员离开可能是无法支付劳动力、家庭关系、职业机会成本、角色冲突或自然人生变更；本例公开仅称经济/个人困难，不授权我们给离开者建立心理/伦理罪责。

H055-3：作者性可能在进入商业公司之后被“看不见地中断”

IGDA署名政策与离职假设显示一种可能的制约：参与产品不保证形成可公开转移的个人作品信用，尤其项目未上市/早期离职。但这不能等于证明公司限制原创就一定降低全国创新人数。需要相同职位、相同年份对照ownership_span / after-hours right / authorship_credit / post-exit project。

Competing evidence

  • NExT/网易内部可以真实扶助员工原型立项（见050），不能把“公司”写成必然掐死作者。
  • 《The Swarm》作者保留新项目转型能力；《RESTART》作者表示会继续；LZY结尾也说在构思下一作，不能把当事人意图等同已产出或永久离开。
  • 先验玩家经验丰富未必保证产品更好，但缺乏玩家经验也可能确实限制原创；二者并不矛盾，区别在REFERENCE BREADTH与PLAYER MODEL CALIBRATION。

6. 下一步必须是匹配的无名者分母，而不是第三十篇漂亮失败文章

Panel-UNFINISHED-2022-CN: 在2022年游戏开发社区一段固定日期范围内，先登记全部公开宣布“开始制作第一款游戏”的创作者，跟踪12/24/48月是否PUBLIC_PROTOTYPE, PUBLIC_SHIP, COLLABORATOR_CHANGE, AUTHORIAL_REENTRY, UNKNOWN。基于他人公开视频只能观察有公开表态者，不能推潜在未表态者的失败率；未见后作不可当事人退出。

Panel-WORKER-ROLE: 受访者自愿提供WORKPLACE YEAR/ROLE, ACTUAL_PROTOTYPE_RIGHT, CREDIT_IF_EXIT, SIDE_PROJECT_PERMISSION, PLAYER_FEEDBACK_CLOSENESS, REENTRY；按雇佣专业游戏岗位/非游戏程序员/学生分层，不问私有NDA细节、不借外部资料推私人家庭史。

Panel-TEAM: 记录2022/2023公开Jam中全体署名至少2人的团队，统一观察24/48月TEAM_SAME, FRAGMENTED_CONTINUED, NO_PUBLIC_TRACE, FORMAL_SHIP; 不把后两者合并，合同权利由本人有权公开的资料决定。

Stop condition: 不能获得至少一个完整入口分母与公开作品/当事人访谈时，055结论只停在机制证实/人数效应UNKNOWN，不写“社会因教育使大多数作者未出生”的数字主张。

7. 书稿的实际人生问题

读者章节候选：《一位游戏主程从未发售自己的游戏；另一人发售之后才听见玩家反对》。

中心不是“他们没有成功，所以应该复盘”，而是三个具体抉择： - 当你知道作品不完善时，能否在保住生计的条件下给陌生人展示小范围试玩？ - 当你发现项目太大或同伴必须离开时，你能否保留以更小范围继续的权利？什么时候STOP THE GAME反而是SAVE THE MAKER？ - 当你进入商业组织，如果未来要成为作品作者，你实际拥有哪些合法公开、可迁移的劳动信用、原型或再次选题资格？

正式reader profile要求补同时期原始设计进展/多次作品并经本人公开许可，不能用2016/2022某篇单独的开发日志编造人物十年生活史。本文件目前用于理论/资料归档与提出下一个可抽样研究，不因有故事性就冒进出版成熟层。

Current verdict: 我们能用具名、2022/2024中国开发者本人反思及2016西班牙团队完整取消日志，证实技术产出、第一件正式作品、真实市场反馈、团队连续生产与雇佣信用可移植是五种不同的门槛。不存在从3名案例得出的国别比例或应试教育强因果；这组样本恰好构成接下来对失败前史的反向调查结构。
