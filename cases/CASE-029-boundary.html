CASE-029 — 边境 / 柳叶刀工作室

  • Case ID: CASE-029
  • Subject: Boundary / Surgical Scalpels Studio
  • Related Claims: C014
  • Research status: RESEARCHING
  • Corpus role: CHINESE COMPARATOR / LONG-CYCLE MULTIPLAYER FAILURE-PRESSURE CASE
  • Last verified: 2026-10-06
  • Evidence Ledger: 来源账本
  • 未核原稿：研究线索存档，继续只作 research lead。

Why this case

Boundary 的研究价值现在已经不只是“失败项目”。公开资料可以同时确认：

  • 三位开发者离开稳定工作，以小核心开始；
  • 早期 PVE prototype 很快暴露高内容成本；
  • 项目随后转向 PvP，并在多年开发中多次调整方向；
  • 零重力 FPS 的 differentiation hook 确实获得市场注意，Early Access 首日付费销量超过 10 万份；
  • 但项目最终没有把 initial acquisition 转成可持续 multiplayer ecosystem，且停服责任存在发行方与开发方争议。

因此本案最适合检验的是：技术 / 题材 novelty 成立时，长开发周期、方向变化和 multiplayer obligation 怎样提高 error-persistence cost；同时避免把失败简化成“没人想玩”。

1. Myth

Myth A — Boundary 失败说明“太空 FPS 没市场”

不成立。E011 的首日付费销售证明产品至少有显著的 novelty / acquisition signal。

Myth B — Boundary 只是发行商毁掉了一个已经完成的好产品

证据不足。发行与开发双方责任仍有争议；制作人自己的回顾也承认核心方向、项目管理、deadline 与更早验证方面存在问题。

Myth C — PVE → PvP 是一次明确降本，所以之后的复杂度天然更低

过强。制作人回顾支持早期 PVE 内容成本压力与转向事实，但 PvP 又引入网络、平衡、留存、匹配和长期玩家生态等另一组 obligation。不能把“少做 PVE 内容”直接等同于总复杂度下降。

2. Context–Situation–Action Snapshot

Era / Production Regime

项目起点处于中国主机 / PC 开发资源逐步增加、China Hero Project 等平台扶持出现的时期。团队试图用零重力 FPS 做国际市场差异化，但在线 PvP 同时要求较高工程质量、持续内容与玩家密度。

Actor Situation

E010 支持“三位开发者离开稳定工作、概念先于公司形成”的创始叙事；China Hero Project 被创始人描述为对小工作室重要。历史股权、虎牙 / 腾讯资金、各阶段团队口径仍需继续审计。

Steam 当前列 Developer = Studio Surgical Scalpels、Publisher = Huya Games（E007）。该字段不能反推完整历史 ownership / financing。

Anachronism Check

不能用 2026 年更成熟的 Steam indie / AI 工具条件倒写早期团队，也不能假设“做 PvP”在当时天然比 PVE 便宜。真正需要比较的是每次 pivot 后新增的 production obligation。

3. Origin

目前可支持： - 三人核心起步； - 创始成员离开稳定工作； - 项目概念与零重力 FPS differentiation 很早存在。

仍 UNKNOWN： - 完整个人履历； - 法律 ownership； - 每轮融资与股权变化。

4. Capability

团队能完成技术辨识度很高的零重力 FPS，并获得强首发购买信号。不能从成品技术表现反推其所有生产环节都成熟，也不能用技术能力替代 multiplayer ecosystem 能力。

5. Runway

China Hero Project 支持被创始人明确认为重要；虎牙、腾讯、其他资金与发行关系仍需分拆核验。当前不估总预算。

6. Production

现有材料支持“长周期、多次方向变化”，但 3–4、7–14、29、40–50+ 等人数口径尚未全部完成同源时间序列，因此不写成精确扩张曲线。

7. Scope

早期 PVE 成本问题是真实决策压力。转 PvP 减少某些手工内容压力，却增加网络、平衡、留存、匹配、反作弊与玩家密度等系统性要求。本案因此是“复杂度迁移”而不是简单“砍 scope”案例。

8. Failure

制作人 E009 的反事实回顾是本案关键证据：如果重新选择，他不会轻易直接做 PvP 太空 shooter；即使仍做，也会更早规划、验证、跑通核心流程并强化项目管理。

这支持 C014 的 error-budget / time-to-player-truth 读法，但仍不足以证明“早验证”是唯一缺失变量。

9. Market

E011 说明 initial hook / acquisition 不是零。真正失败发生在把注意力与购买转成长期活跃 multiplayer ecosystem 的过程中。

因此不能把“首发卖得动”和“live ecosystem 可持续”当成同一个 market truth。

10. Environment

平台扶持、公司融资、发行商和中国 PC / console 市场环境都可能改变项目可持续投入时间。它们既可能提供必要 runway，也可能提高错误方向继续存在的上限；后一层目前仍是待量化机制。

11. Luck

发行关系、市场 timing 与同类竞争可能影响结局，但当前没有证据允许用 luck 替代生产和产品机制分析。

12. Verdict

当前最强结论是：

Boundary 不是“没人要的怪点子”，而是一个成功制造 novelty / acquisition signal，却在长期生产与 multiplayer ecosystem 上承受高 error-persistence cost 的案例。

这使它可以正式参与 C014；但停服责任、完整资金链、团队扩张与各次 pivot 的具体因果仍保持 OPEN。

13. Transfer

可迁移： - 把“多久知道错”与“错一次花多少”列为立项变量； - 区分 acquisition validation 与 retention / ecosystem validation； - 每次 pivot 都重新计算新增 obligation； - 技术 novelty 不能替代 core-loop / community economics 验证。

14. Non-transfer

不可直接复制 / 推断： - China Hero Project 等平台扶持； - 历史融资与大公司关系； - 太空 FPS 题材本身； - 任何单一责任归因。

Creator Life / Decision Audit

  • Audit status: PARTIAL
  • Life stage: 三位创始开发者离开稳定工作后开始；完整年龄、婚育与 household 阶段 UNKNOWN。
  • Household: relationship / children / housing / family support 均 UNKNOWN。
  • Runway: China Hero Project 支持被创始人认为重要；虎牙、腾讯及其他资金/股权/发行关系尚未完成拆分；不得估总预算。
  • Household burn: UNKNOWN；当前只知道从稳定工作转创业发生了真实职业收入风险。
  • Exit / recovery: UNKNOWN — 有稳定工作前史，但项目长期化之后的再就业/回撤条件没有公开闭环。
  • Capability vector: 零重力 FPS、networked shooter、技术表现与国际市场 hook 较强；multiplayer ecosystem / live-service capability 是否同步成熟不能从成品表现反推。
  • Problem ownership: MIXED / UNKNOWN CONTROL BOUNDARY — 创始概念很早由核心团队提出，但后续融资、发行、benchmark 与 approval 权限未核清。
  • Validation architecture: early PVE prototype / cost realization → PvP pivot → China Hero / public exposure → long development → Early Access >100k paid first-day signal → retention/ecosystem failure → shutdown。
  • Reality adjudication: PARTIAL / LATE — PVE 成本很早迫使团队改方向；但 acquisition signal 与 sustainable multiplayer truth 被分开验证，后者到较晚阶段才充分暴露。
  • Capability capture risk: MEDIUM / HYPOTHESIS — 高技术/novelty 可持续制造外部关注，但当前不足以证明技术强项本身主导了 scope capture。
  • Market sufficiency / legibility: STRONG acquisition / WEAK ecosystem sufficiency — 首日购买证明 hook 可读；长期 multiplayer liquidity/retention 没有成立。
  • Capability scaling: 技术与团队规模长期扩大，但 live ecosystem 未形成可持续闭环。
  • Major unknowns: founders household economics、ownership/股权、各阶段团队规模、项目预算、publisher control、DAU/retention。
