# 游戏官网制作与交付

先读目标项目的 AGENTS、README、WRITING_GATE 和直接相关来源。项目自己的事实、作者选择与当前授权优先。本 Skill 提供制作方法；不授予游戏代码、美术定稿、付费生成、账号配置或发布权限。用户已经明确批准的范围继续执行，不重复索取批准。

## 接续前核对

锁定网站唯一工作目录、Git remote/HEAD/dirty 状态、公开目录、现有托管身份、主站与镜像关系。沿迁移指引找到现行入口，不能选“最近见过的 dist”。保留并行修改；不为整理目录覆盖 Git 元数据、合并独立历史或重新建站。

DragonFly 接收本 Skill 时，另读 [DragonFly 交接](references/dragonfly-handoff.md)。其中状态有日期，接续时重新读取现行文件，不把这份交接当永久事实。

## 制作与编辑

1. **让新读者理解游戏。** 先明确扮演/操纵对象、威胁、行动和可体验的局面，再安排世界背景、画面、团队与合作入口。面向发行商、资助方也要讲清作品吸引力。按作者要求保留气氛与悬念，公开页面不堆内部实验、待定清单和自审状态；仍不得捏造已完成功能、日期、证言或合作成果。
2. **把参考落到本站。** 每个采用的参考记录“实际观察 → 借鉴做法 → 本站具体位置 → 改后比较”。内容抓取、真实截图和推断分开写。无法渲染的站点不能宣称已做视觉审查。借信息顺序、画面比例、节奏和交互目的，不复制素材或强套配色。
3. **从项目美术提炼视觉。** 读取现有 DESIGN/品牌样本；必要时更新同一主文件，说明字体、色彩、图片裁切和间距如何服务作品。用少量可比较方向解决真实差异，避免默认卡片阵列、装饰标签和反复口号。图片各自承担说明作用，宁可留白也不重复堆同一概念图。
4. **核对素材与语义。** 沿现有素材来源文件核实版本和公开范围，区分概念图、宣传图、战术示意与实机。公开展示许可不等于最终品牌/游戏内采用。改文案不能改变上限、触发条件、对象关系或实施状态。原图保留，网页衍生图另存；压缩不悄悄改画意。
5. **按用途审校双语。** 使用项目已有 Writing Gate，不把角色口吻套给制作方官网。英文与中文各自通读，删重复解释、模板反转和无具体内容的拔高。正文、标题、按钮、图注、替代文本、元信息一起检查。保留作者刻意选择的座右铭与立场；不能把去模板化当成抹平个性。
6. **沿用现有技术。** 简单静态站无需为交付额外安装框架或构建链。遵循项目的双语实现：同位 span、语言词典或独立路由都可；重点是默认语言、切换/重载和内链一致。词典方案要对比静态英文与运行后英文，查遗漏字段、露出的键名和交互步骤文本。

## 验收与发布

读取 [浏览器验收](references/browser-qa.md)。按照实际页面选桌面、常见手机和最窄支持宽度，检查懒加载后的图片、菜单、键盘、灯箱、页面特有交互、语言与路由。截图要实际查看。未在窄视口实测导航开合、首屏标题与图注的页面不得进入发布。测试数量、HTTP 200、文件哈希或脚本成功均不能证明视觉/文案已经被作者接受。

可复用工具：

- `scripts/audit-site.mjs`：按 JSON 配置运行浏览器视口、图片、内链、语言、交互和截图检查。仅在宿主允许直接使用已安装 Playwright 时运行；否则用宿主浏览器工具执行同一场景，不绕过限制或自行安装浏览器。
- `scripts/compare-public-files.mjs`：只读比较两个公开目录的完整文件集合及 SHA-256，报告新增、缺失或内容差异，不复制、不删除。

发布或跨平台同步时读 [发布与恢复](references/publishing.md)，沿用平台官方 Skill/工具。只同步公开目录，保留托管项目身份；固定已推送源码提交与对应归档。确认本次版本的部署结果，必要时对比线上正文/资源。发布镜像时核对 canonical、hreflang、og:url、分享图与 sitemap 的主站选择。

用户要求借助 OpenDesign 时读 [OpenDesign 交接](references/opendesign.md)，复用安装版本的官方 Skill。不得把自己手写的页面称作 OpenDesign 生成。DragonFly 作者已选定 Local Codex；后续继续沿用，不再询问 Cloud 充值，详见该交接中的项目模式约定。

## 完成交接

更新已有维护入口和验收记录，写清源码位置、实际版本、公开 URL、通过/失败/未做的检查及仍需作者决定的内容。发布回执可记录提交、版本与部署标识，但留在公开目录之外。没有做过的真机、Safari、性能跑分、邮箱收信或申请提交不能写成通过。

来源与方法边界见 [经验依据](references/experience.md)。迁移流程和工具，不迁移 KWP 的世界观、品牌、素材、域名、账号或固定检查数量。
